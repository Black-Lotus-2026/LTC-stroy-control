# Единственная модель детекции

Приложение использует `construction-yolov8m-v2.pt`: обученную YOLOv8m, 28 каналов головы и 25 семантических категорий. SHA256:

`ce1195cb295534a08b3cdbba9ccf8c7a0c962875437ba49c4c6e68bbe3a4fb40`

Артефакт: закрытый Kaggle notebook `isaevsemyon/ltc-target28-yolov8m-960`, версия 2, output `run/weights/best-deployment.pt`, 103841879 байт. Веса не входят в публичный Git. Сначала скачайте их через свой авторизованный доступ к Kaggle, затем установите:

```sh
cd backend
python -m app.scripts.install_trained_detector /secure/path/best-deployment.pt
```

Установщик проверяет точный SHA перед установкой и не перезаписывает другой файл. В рабочем стенде веса находятся в `backend/weights/construction-yolov8m-v2.pt`. Для другого сервера требуется тот же приватный артефакт. Настройка `YOLO_WEIGHTS_PATH` задаёт расположение, но не разрешает другую модель: несовпадение SHA приводит к недоступности детектора. Автоматической загрузки COCO/других YOLO нет.

API и Celery используют один и тот же сервис и файл; каждый процесс кеширует свой экземпляр. Разрешение по умолчанию 960, порог 0.5, Ultralytics закреплён на 8.3.203. Сначала объединяются эквивалентные семантические каналы, затем NMS и межклассовое удаление дублей с сохранением координат/класса/score самой уверенной исходной гипотезы. Отслеживания уникальных машин это не доказывает.

Голова обучена на 25 категориях; в YOLO активны 24. `grader` отключён **до** выбора класса/NMS из-за ошибок исходной разметки. Рабочие и крюки не объединяются с машинами. Выходные confidence не откалиброваны, ошибки классов возможны. По умолчанию действует `CONSTRUCTION_POLICY=shadow`: только детекции. Для явного включения регистрации нарушений задайте `CONSTRUCTION_POLICY=enforce` и JSON-список `CONSTRUCTION_APPROVED_CLASSES` с классами правил (кроме `grader`). API и worker должны получать одинаковые значения. Это эксплуатационное разрешение, а не подтверждение точности модели: `quality_verified=false` сохраняется, события требуют проверки человеком. Нерабочий детектор и ошибки чтения кадров не считаются отсутствием техники.

Фото: `/api/v1/videos/detect-photo` использует эту же YOLO. Только успешный пустой результат запускает VLM; нужен действующий inference `OPENROUTER_API_KEY` в backend `.env`, `PHOTO_VLM_ENABLED=true`, модель `PHOTO_VLM_MODEL` (по умолчанию `openai/gpt-4o-mini`). Пустой/ошибочный ответ VLM обозначается явно. VLM допускает 25 категорий, включая грейдер только при видимой характерной геометрии; это независимая визуальная гипотеза, а не повтор ошибочного YOLO-класса. Секреты остаются на сервере. При вызове VLM фото отправляется OpenRouter после удаления метаданных и уменьшения; интерфейс сообщает об этом.

Видео и камеры: `/api/v1/videos/detect-frame`, фоновые задачи и перепроверки используют только YOLO, без VLM. Загрузка видео проверяет реальное декодирование и метаданные; чтение файла выполняется потоково. Интерфейс анализирует кадры при воспроизведении, а не заявляет готовый анализ всей записи в момент загрузки.

Для Docker сначала создайте `backend/.env` из `backend/.env.example` и задайте ключ там: API и worker читают этот файл через `env_file`, без пустого переопределения ключа. Приватный файл весов должен существовать до запуска/сборки. Bind mount `./backend:/app` включает установленный файл. Никакие другие `.pt`, приватные `.env`, тренировочные данные или записи камер в Git не добавляются. Проверьте `/api/v1/videos/detector-status`: `ready=true`, `profile=construction_trained`, правильный `model_sha256`.
