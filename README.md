## Ключевые возможности и инновации

### 1. Синхронный мультикамерный анализ объекта
* **Анализ сразу всех камер на объекте:** Система обрабатывает не единичный изолированный ракурс, а **все подключенные видеопотоки и сетевые IP-камеры объекта одновременно**.
* **Единое агрегированное множество техники:** На строительной площадке одна камера неизбежно имеет «слепые зоны» (за перекрытиями, монолитными пилонами или бытовыми городками). Детекции со всех камер синхронно объединяются в **ОДНО общее множество для текущего этапа**, исключая слепые зоны и взаимно дополняя ракурсы.

### 2. Всеракурсная фотофиксация доказательств
* **Снимки со всех камер в момент проблемы:** В момент выявления технологического отклонения сервис мгновенно выполняет захват кадров со **всех активных камер** строительного объекта.
* **Мини-альбомы по ошибкам:** Снимки группируются в структурированный фотоальбом инцидента.
* **Иерархия отчетности:**
  * В сводный отчёт и экспресс-карточку выводится опорное фото с **первой (основной) камеры**, исключая дублирование одинаковых ракурсов;
  * При клике и переходе в фотоархив открывается **полный фотоальбом нарушения со всеми ракурсами**, позволяя инженеру технадзора всесторонне оценить ситуацию.

### 3. Интеллектуальный движок сопоставления с календарным планом
* **46 этапов и нормативный классификатор:** Модуль [`StageMatcher`](./backend/app/services/stage_matcher.py) автоматически связывает пользовательские наименования этапов из графика СМР с нормативным классификатором Мосгосстройнадзора (`info/final_pars.csv`).
* **Вероятностный профиль спецтехники:** Для каждого этапа рассчитывается технологический профиль:
  * **Обязательная техника (`MANDATORY`, $P \ge 80\%$)** — отсутствие влечет статус «Ошибка» (риск срыва темпа);
  * **Рекомендованная техника (`RECOMMENDED`, $50\% \le P < 80\%$)** — отсутствие влечет статус «Предупреждение»;
  * **Нехарактерная (лишняя) техника (`UNCHARACTERISTIC`, $P < 20\%$)** — фиксация влечет статус «Ошибка» о нарушении технологической дисциплины.
* **Темпоральный 30-секундный буфер:** Исключает ложные срабатывания при кратковременных технологических маневрах техники.

### 4. Изоляция рабочих областей и безопасность
* **Разделение рабочих областей:** Пользователи видят и администрируют только закрепленные за ними строительные объекты и камеры.
* **Ролевая модель:** Администраторы имеют сквозной мониторинг по всей Москве; инспекторы технадзора и подрядчики работают в изолированных пространствах.
* **Текущее системное время в шапке:** Реальное системное время и дата на русском языке с поминутной синхронизацией.

## Разделы веб-интерфейса платформы

| Раздел | Назначение | Ключевые возможности |
|---|---|---|
| **Наблюдение** | Оперативный мониторинг стройплощадки | Онлайн-плеер RTSP/HTTP потоков и загрузка видео; отрисовка bounding boxes; статус синхронизации со спецтехникой; всплывающие алерты. |
| **Фотоархив** | Доказательная база нарушений | **Альбомы по ошибкам:** группировка снимков со всех камер в момент нарушения; полноэкранный зум; фильтрация по статусам и камерам. |
| **Прогресс** | Календарный план СМР | Интерактивная диаграмма Ганта; импорт графиков из Excel (.xlsx); инструмент каскадного сдвига зависимых этапов при отставаниях. |
| **Аналитика** | Профили требований к технике | Радарные диаграммы присутствия техники по этапам; возможность ручной калибровки требований под конкретный ППР. |
| **Отчёты** | Документирование и аудит | Суточные сводки смены; журнал нарушений с фотофиксацией; **экспорт в PDF с выбором произвольного диапазона дат**. |
| **Настройки** | Администрирование инфраструктуры | Управление объектами, зонами, добавление IP-камер, проверка связи, регулировка окна контроля нарушений. |

## Быстрый запуск

### 1. Запуск в Docker Compose (Рекомендуемый)

Убедитесь, что установлены **Docker** ($\ge 24.0$) и **Docker Compose** ($\ge 2.20$).

```bash
# Клонируйте репозиторий
git clone https://github.com/Black-Lotus-2026/LTC-stroy-control.git
cd LTC-stroy-control

# Запустите все сервисы одной командой
docker compose up --build -d
```

После старта система разворачивает 4 изолированных сервиса:
- **Веб-интерфейс**: [http://localhost:5173](http://localhost:5173)
- **API Swagger**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **База данных PostgreSQL**: `localhost:5433` (`stroy_control`)
- **Redis / Celery**: `localhost:6380`

### 2. Локальный запуск без Docker

#### Бэкенд (Python 3.11+):
```bash
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1    # Для Windows PowerShell
# source venv/bin/activate    # Для Linux/macOS

pip install -r requirements.txt
$env:DATABASE_URL="sqlite:///./stroy_control.db"
uvicorn app.main:app --port 8000 --reload
```

#### Фронтенд (Node.js 18+):
```bash
# В корневой папке проекта:
npm install
npm run dev
# Интерфейс откроется по адресу http://localhost:5173
```

### 3. Автоматизированные тесты
```bash
pytest backend/tests/
# 37 из 37 тестов проходят успешно (100%)
```

## Перспективы развития (Roadmap)

Векторы дальнейшего масштабирования и развития функционала платформы:

1. **ИИ-агент автоматизированного планирования по ПОС и ППР**:
   - Автоматический семантический парсинг и анализ строительной документации: **Проекта организации строительства (ПОС)** и **Проекта производства работ (ППР)**.
   - Автономный агент извлекает ведомости потребности в машинах и механизмах, строительные генеральные планы (стройгенпланы) и формирует структурированный календарный график СМР с точной привязкой нормативной техники к пространственным зонам без ручного ввода.

2. **Интеграция мультимодальных моделей (VLM) для глубокого анализа проблем**:
   - Подключение Vision-Language Models (VLM) в качестве второго экспертного контура валидации аномалий.
   - VLM анализирует пространственный контекст всей сцены целиком, выявляя скрытые причины отклонений: технологические паузы (схватывание бетона, пересменка, ожидание армирования), погодные факторы (затопление котлована грунтовыми водами, наледь), пространственные конфликты смежных бригад.
   - Автоматическое составление развернутых экспертных заключений и рекомендаций для инженеров технадзора по оптимизации темпа работ.

3. **Бесшовная интеграция с ЕЦХД Москвы**:
   - Масштабирование на тысячи городских строительных объектов через интеграцию с Единым центром хранения данных города Москвы (ЕЦХД) и автоматической выгрузкой инцидентов в аналитические панели Стройкомплекса.
