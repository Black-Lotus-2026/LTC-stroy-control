# Строй-контроль

Комплексная цифровая платформа автоматизированного контроля строительных площадок: интеллектуальный мониторинг видеопотоков, распознавание строительной техники (YOLO), сопоставление с календарным графиком СМР и двухуровневый аудит нарушений регламентов с VLM-верификацией (Google Gemini Vision).

Команда **Black Lotus**. Разработано в рамках хакатона Департамента градостроительной политики города Москвы.

## 1. Как определяется необходимая техника

Определение перечня спецтехники, которая обязана или может находиться на объекте, выполняется автоматически на основе календарного графика СМР:

1. **Определение активного этапа СМР**:
   - Система сопоставляет текущую календарную дату с плановыми интервалами дат в графике производства работ (диаграмма Ганта).
   - При задержках или сдвигах сроков поддерживается интерактивный каскадный пересчет дат зависимых этапов СМР.

2. **Сопоставление этапа с нормативным классификатором (`StageMatcher`)**:
   - Модуль [`backend/app/services/stage_matcher.py`](file:///D:/LDT_2026/backend/app/services/stage_matcher.py) сопоставляет пользовательское наименование этапа из сметы/графика (например, *«Устройство монолитных железобетонных конструкций выше отм. 0.000»*) с нормативным датасетом Департамента градостроительной политики Москвы (`info/final_pars.csv`).
   - Используются алгоритмы нормализации текста, токенизации, лемматизации и нечёткого сопоставления (fuzzy token match / TF-IDF) для поиска релевантного нормативного этапа.

3. **Вероятностное профилирование спецтехники**:
   - Для найденного нормативного этапа вычисляется вероятностный профиль присутствия каждого типа техники $P(\text{техника} \mid \text{этап})$.
   - Техника категоризируется по четырём уровням требований:
     - **Обязательная (`MANDATORY`, $P \ge 0.80$)**: техника, отсутствие которой на этапе делает невозможным выполнение работ (например, башенный кран и автобетоносмеситель при монолитных работах, экскаватор при разработке котлована). Отсутствие влечёт статус **🔴 ERROR**.
     - **Рекомендованная (`RECOMMENDED`, $0.50 \le P < 0.80$)**: вспомогательная техника высокой вероятности (например, погрузчик, автокран). Отсутствие влечёт статус **⚠️ WARNING**.
     - **Допустимая (`NEUTRAL`, $0.20 \le P < 0.50$)**: техника, допустимая для технологических операций смежных бригад.
     - **Нехарактерная / Лишняя (`UNCHARACTERISTIC`, $P < 0.20$)**: техника, которой категорически не должно быть на данном этапе (например, асфальтоукладчик или каток при рытье котлована или устройстве фундаментной плиты). Появление фиксируется как критическое нарушение **🔴 ERROR**.

4. **Индивидуальная калибровка и оверрайды**:
   - Главный инженер и специалист технадзора в разделе **«Аналитика»** имеют возможность просматривать радарные диаграммы профилей этапов и вручную скорректировать требования под специфику конкретного ППР (проекта производства работ).

## 2. Как определяется техника на видео

Детекция спецтехники и контроль непрерывности работ производятся в реальном времени с использованием связки нейросетевого зрения и темпорального анализа:

### Технологический стек детекции
- **Архитектура**: сверточная нейросеть **YOLO (You Only Look Once)**, адаптированная под детекцию объектов строительства.
- **Классы распознаваемой техники (10 основных классов)**:
  1. Экскаватор (`Excavator`)
  2. Самосвал (`Dump truck`)
  3. Бульдозер (`Bulldozer`)
  4. Башенный кран (`Tower crane`)
  5. Автокран (`Truck crane`)
  6. Автобетоносмеситель (`Concrete mixer`)
  7. Бетононасос (`Concrete pump`)
  8. Фронтальный погрузчик (`Loader`)
  9. Экскаватор-погрузчик (`Backhoe loader`)
  10. Каток / Дорожная техника (`Roller / Road machinery`)

### Механизм детекции на видео
1. **Захват кадра (Frame Extraction)**:
   - Фронтенд-плеер (`VideoPlayer` / `Monitoring`) работает как с загруженными видеозаписями (MP4, MOV, AVI), так и с RTSP/HLS-видеопотоками сетевых IP-камер стройплощадки через бэкенд-прокси.
   - С шагом анализа (1–2 сек) текущий кадр проецируется на HTML5 `<canvas>` и конвертируется в изображение высокого разрешения (`image/jpeg`).

2. **Инференс нейросети**:
   - Кадр передаётся в микросервис детекции (`/api/v1/videos/detect-frame`).
   - Модель возвращает массив распознанных объектов с нормализованными координатами bounding boxes и коэффициентом уверенности ($conf \in [0..1]$).
   - Плеер отрисовывает рамки с цветовой индикацией и русскоязычными маркерами непосредственно поверх видеопотока.

3. **Темпоральное окно контроля (30-секундный буфер)**:
   - В реальных условиях стройплощадки техника может кратковременно перекрываться конструкциями, колоннами или выходить из поля зрения камеры на несколько секунд.
   - Во избежание ложных срабатываний система накапливает уверенные детекции ($conf \ge 60\%$) в течение скользящего окна контроля (по умолчанию **30 секунд**, настраивается в интерфейсе от 5 до 120 сек).
   - По завершении 30-секундного окна формируется сводное множество фактически присутствовавшей техники, которое передаётся в `RuleEngine`.

4. **Двухуровневая VLM-верификация (Google Gemini Vision)**:
   - При выявлении инцидента оператор может запустить VLM-верификацию кадра.
   - Мультимодальная модель анализирует пространственный контекст сцены целиком, выявляет скрытые факторы (погодные условия, технологические паузы) и предоставляет текстовое заключение.

5. **Моментальная фотофиксация доказательств**:
   - При срабатывании правила зафиксированный кадр немедленно привязывается к инциденту, отправляется в хранилище снимков и становится доступен:
     - во всплывающем уведомлении с миниатюрой нарушения;
     - в фотоархиве с полноэкранным зумом и временной меткой;
     - в суточном отчёте со ссылкой на доказательство.

## Разделы веб-интерфейса

1. **Наблюдение (`monitoring`)**:
   - Видеотрансляция и загрузка файлов с камер строительной площадки.
   - Отображение боксов детекции YOLO в реальном времени.
   - Всплывающие уведомления о нарушениях с превью кадра.
2. **Фотоархив (`archive`)**:
   - Единая база фотофиксаций всех нарушений с привязкой к камерам, участкам и времени.
   - Фильтрация по статусам (Ошибки / Предупреждения / Поиск).
   - Полноэкранный просмотр кадра в максимальном разрешении.
3. **Прогресс (`progress`)**:
   - Интерактивный календарный план СМР (диаграмма Ганта).
   - Загрузка графиков в формате Excel (.xlsx).
   - Инструмент каскадного сдвига сроков этапов при задержках.
4. **Аналитика (`analytics`)**:
   - Вероятностные профили спецтехники на этапах СМР.
   - Радарная диаграмма распределения парка техники.
   - Редактор индивидуальных переопределений требований к технике.
5. **Отчёты (`reports`)**:
   - Суточная сводка за смену (08:00–20:00).
   - Подсчет критических ошибок и предупреждений.
   - Журнал нарушений с фотофиксацией и ссылками на фотоархив.
   - Экспорт в PDF и генерация шеринг-ссылки.
6. **Настройки (`settings`)**:
   - Управление объектами строительства и зонами стройплощадки.
   - Настройка IP-камер (RTSP/HLS).
   - Регулировка окна темпорального контроля нарушений (в секундах).

## Запуск проекта

### Требования
- **Docker** и **Docker Compose**

### Быстрый старт в Docker

```bash
docker compose up --build
```
или через Makefile:
```bash
make up
```

После старта будут доступны следующие сервисы:

| Сервис | Адрес | Описание |
|---|---|---|
| **Веб-интерфейс** | http://localhost:5173 | Полнофункциональный интерфейс платформы |
| **API Backend** | http://localhost:8000 | FastAPI бэкенд |
| **Swagger UI** | http://localhost:8000/docs | Интерактивная документация REST API |
| **PostgreSQL** | `localhost:5433` | База данных (`stroy_control`) |
| **Redis** | `localhost:6380` | Брокер очередей Celery |

### Полезные команды

- Загрузка нормативного справочника видов работ:
  ```bash
  make import-catalog
  ```
- Остановка контейнеров:
  ```bash
  make down
  ```
- Запуск тестов:
  ```bash
  docker compose exec api pytest
  ```

## Стек технологий

- **Backend**: Python 3.12, FastAPI, SQLAlchemy 2 (async/sync), Alembic, Pydantic v2, Celery, Redis.
- **Computer Vision & AI**: Ultralytics YOLO (детекция 10 классов строительной спецтехники), Google Gemini Vision (VLM-валидация контекста сцены), NumPy, Pillow.
- **База данных**: PostgreSQL 16.
- **Frontend**: React 19, TypeScript, Vite, SVG Charts, Gantt Engine, Canvas Image Processor.
- **Инфраструктура**: Docker, Docker Compose.
