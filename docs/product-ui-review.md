Изменения рабочих данных заказчика и внешняя рассылка не выполнялись.

## Готово

- Главный экран — отклонения. Четыре основных раздела: Отклонения, Камеры, График, Отчёты. Фотоархив и Правила контроля доступны в «Дополнительно». Настройки отдельно внизу меню.
- Один выбор объекта и, где нужен, площадки. Из шапки убраны часы, дата, фиктивная актуальность и повторные счётчики. Профиль — компактное меню; на мобильном доступен выход.
- Отклонение: название, фактические время/статус/ответственный, одна кнопка цены бездействия. Открытые/Все считают только соответствующие случаи текущего объекта/площадки.
- Мини-окно сохраняет график дополнительных затрат, условие задержки, сценарную маркировку и ⓘ со ставками/источником. Числа берутся из прежнего калькулятора. Информационному восстановлению связи финансовое действие не предлагается.
- Камеры: список источников и просмотр, вторичные действия свёрнуты. Нет stock-изображения вместо RTSP, ложного LIVE, FPS/задержки или успешного «формирования отчёта» без результата. Скачать кадр можно только при доступном изображении.
- График: плановые полосы и один выбранный этап; редактирование сроков открывается явно. Импорт, демо и сдвиг сохранены, редкие действия свёрнуты. Прошедшие плановые даты не выдаются за фактическое завершение.
- Правила: техника и требование в таблице, отдельный режим редактирования. Убраны дублирующая диаграмма и проценты справочного профиля. Нет локальной имитации успешного сохранения после ошибки API.
- Отчёты: журнал, поиск, тип события, согласованные счётчики. Компактная дата самого события. Печатная форма открывается только через экспорт; сохранён существующий механизм печати/PDF. Фотоархив показывает реальные альбомы либо честное пустое состояние; нет подставных фото.
- Настройки: без третьего выбора объекта; удаление за дополнительным меню. Сохранения неактивны до изменения, интервал — вторичное действие.

### После просмотра пользователем

По прямой просьбе возвращён прежний подробный вид Ганта: даты и длительность в строках, цветные полосы с подписями, заметная линия «Сегодня», быстрые −1д/+1д. Подсветка отражает положение планового периода, а не подтверждённое выполнение работ. Проверки доступа и сохранение только подтверждённого ответа API остаются. Другие разделы и новый логотип не менялись.

## Исправления достоверности на затронутом пути

1. Ошибки загрузки объектов/плана/событий показываются явно. Не создаётся объект и не подставляются демо-камеры, расписание или вероятности из-за ошибки сети.
2. Объект/площадка фильтруют события во всех представлениях. Привязка нового события берётся из камеры, а не первой площадки. Для видео без выбранной площадки она не угадывается. Альбом и наблюдения объединяются только внутри площадки; временные окна раздельные.
3. Повторная запись сервера заменяет существующий UUID/code, сохраняя серверный статус и время первого наблюдения. Строка случая появляется после успешного сохранения. Ошибка сохранения видна.
4. Наблюдателю не предлагается менять статус и не создаются автоматические записи от просмотра. Инспектору не предлагается переход в закрытый для него раздел правил.
5. Оценка отсутствия техники начинается только после успешного получения правил именно этого stage.id. Ошибка видна, есть повтор загрузки. Ответ другого этапа не попадает в кеш. Отложенный ответ детектора после смены источника игнорируется.
6. Schedule endpoints требуют авторизацию и точный UUID/владение объектом. Удалён fallback неизвестного этапа к первому; очистка без project_id запрещена. Импорт плана передаёт токен.
7. API событий возвращает zone_id, first_seen_at и confidence. Клиент не подставляет фиктивное время, исполнителя или уверенность 95–96%.

## Запуск и ручная проверка

Подготовленный локальный стенд: http://127.0.0.1:5173; API http://127.0.0.1:8000. Вход и команды запуска: [management-demo.md](management-demo.md). Установка новых зависимостей не нужна. API перезапущен с актуальными полями и правами расписания; worker не менялся.

1. Отклонения → «Демо · проверка подачи самосвалов» → Цена бездействия → график/ⓘ → название случая в отчётах.
2. Объект B показывает пустой журнал; возвращение в A возвращает его записи.
3. График → выбранный этап → Изменить сроки → Отмена. Правила контроля → Редактировать → Отмена. Настройки изначально не предлагают повторно сохранять прежние значения.
4. Камеры без потока показывают отсутствие изображения; RTSP требует шлюз. Это ожидаемое ограничение, а не успешная интеграция.

Методика денег не менялась: [контрольный пример](../data/demo_management/README.md), [кривая](simple-cost-ui.md). Три сценария: 44 000 / 68 000 / 112 000 ₽; перенос 0 / 0 / 4 рабочих часа. Разница 68 000 ₽ — условное сравнение заданных входов, не фактическая экономия.

## Точные оставшиеся задачи

- P0 до внешнего размещения: закрыть оставшиеся legacy CRUD/медиа endpoints и заменить default JWT secret; полная матрица чужих объектов для них. Schedule, management и incidents имеют отдельные guards, это не делает весь старый API защищённым.
- P1 интеграции: настроить RTSP→HTTP/MJPEG/WebRTC gateway и провести реальные прогоны CV, недоступности модели, нескольких камер/площадок и времени записи. В этой итерации проверены UI, код и контракты, а не оборудование.
- P1 бизнес-входы: подтвердить ставки/доступность техники/график на объекте; дать отдельный компактный редактор профиля, если требуется самостоятельное заполнение без API. Отсутствие входов остаётся unavailable.
- P2: проверить финальный печатный PDF в целевом браузере и реальном фотоальбоме. Форма экспорта и существующий генератор сохранены, новая визуальная печать/подпись не объявляется проверенной.
- P2: переносить старые правила на единый backend rule engine; frontend legacy CV-оценщик остаётся, но теперь требует подтверждённые сервером профили. Длительные полевые прогоны и единый authoritative rule-version — отдельная работа.
- Следующий бизнес-этап: поручения/контроль реакции и другие пункты исходного backlog. Они не добавлялись ради расширения UI.
