# Цена бездействия: простой экран

Проверено 16 октября 2026. Пользовательский путь: случай отклонения → одна кнопка **Цена бездействия** → мини-окно. В нём название-ссылка на случай, заметная подпись «Сценарная оценка», сумма, условие «Если задержка составит…», график «задержка в рабочих часах → дополнительные затраты» и круглая ⓘ с расшифровкой. Недостаточность оснований видна рядом с суммой. Начало отсчёта расчёта показано отдельно; оно не выдаётся за время начала фактического ущерба. Наведение на график выбирает время; клавиатура поддерживает стрелки, Tab и Escape. Закрытие возвращает фокус на кнопку. Окно адаптируется к узкой ширине.

Раздел «Отклонения» содержит короткие строки только выбранного объекта. Кнопка есть также у случаев фотоархива, отчётов и в уведомлении о новом отклонении. Рабочая структура приложения сохранена. Подробный ManagementPanel оставлен в исходниках, но не загружается в пользовательском пути.

## Расчёт и происхождение

`GET /api/v1/incidents/{uuid}/inaction-cost` проверяет авторизацию и принадлежность объекта. Берётся последний законченный/частичный/needs_input запуск именно этого случая. Его snapshot неизменен. Если запуска нет, допустим только сохранённый профиль, явно привязанный к этому incident_id; общий или чужой профиль не используется.

`services/management/inaction_curve.py` через существующий `ScenarioCalculator` пересчитывает сценарий no_action для 17 точек от 0 до заданного в нём recovery_work_hours и добавляет заданные времена других сценариев внутри горизонта. Меняется только длительность восстановления в копии snapshot. Ставки, ресурсы, календарь, график и затронутость остаются из исходного случая. Горизонт не продлевается автоматически. Денежная арифметика — Decimal, суммы API — строки; Number в браузере используется для координат графика. Наведение показывает ближайшую рассчитанную точку.

Для demo baseline: простой = (8 000 + 4 000) × t; продление = 4 000 × max(0, t − 4). Точки: 0 ч → 0 ₽; 2 ч → 24 000 ₽; 4 ч → 48 000 ₽; 8 ч → 112 000 ₽. При 8 ч подсказка показывает 96 000 ₽ простоя и 16 000 ₽ продления графика. Суммы условные, `is_actual_damage=false`; дата оценки и demo помечены в окне.

Это общие дополнительные затраты сценария бездействия. **68 000 ₽** из исходного контрольного теста — разница между 112 000 ₽ бездействия и 44 000 ₽ быстрого вмешательства (включая стоимость действия), а не значение этой кривой при 8 ч. Фактическая экономия не заявляется.

Неполные ставки/график дают null/partial, окно не рисует фиктивный график. API возвращает читаемые `needs`: конкретную ставку ресурса, продление, состав затрат или проблему графика. Без привязанного расчёта возвращается unavailable: нужны привязанные ресурсы/ставки и график со сроком восстановления. Окно показывает, какие входы подготовить и кому передать их: сохранённому ответственному или владельцу объекта. Это справочная подсказка, поручения и внешняя отправка не создаются. Для новых реальных случаев ещё нужно заполнить собственные входы через профиль API; автоматического назначения ставок нет. Недостаток наблюдений отмечается отдельно от возможности условного расчёта. Нажатие не вызывает LLM, не создаёт запуск и не меняет сохранённую карточку.

## Правки после оценки дизайнера

- Сценарность поднята к сумме, повтор «Демо» в названии убран только в подписанном demo-режиме. Длинная служебная строка заменена ясным началом отсчёта. «Основания требуют проверки» больше не спрятано в мелкой подписи.
- Название открывает и выделяет существующую карточку в «Отчётах», прокручивает её в поле зрения и переводит фокус. Для перехода из другого объекта выбирается объект самого случая. В карточке показываются сохранённый ответственный из БД и все поддержанные статусы, включая «В работе»/«Устранено».
- ⓘ сохраняет круглый знак, область нажатия 44×44. Поддерживает hover, фокус, закрепление нажатием и закрытие повторным нажатием/Escape. Данные `basis` в каждой точке — только реально использованные компоненты калькулятора: ставки, единицы, множитель, источник, подтверждение и расчётный период. Указано, что горизонт задан сценарием; отдельно показан сдвиг контрольной точки. Источник не заменяется общей фразой; дата снимка доступна как начало отсчёта в окне.
- Подсказка над графиком делает выбор времени заметным; выбор поддерживает также нажатие на график. Расчёт, ставки и LLM путь не менялись.
- Дизайнер повторно прочитал реализацию: существенных UX-блокеров не обнаружил. Браузерные проверки выполнил интегратор, дизайнер не выдавал свою проверку кода за браузерную.

Нового редактора профиля нет: подготовка реальных ставок и графика пока выполняется через существующий API. Пустое состояние даёт следующий шаг и ответственного; это не автоматическое создание входов и не подтверждённая готовность новых кейсов к расчёту.

## Проверки

- Полный backend после правок дизайнера: **177 passed, 0 skipped**, отдельная PostgreSQL 16 (4,80 с). Затронутые API/curve модули: **38 passed**. Проверены происхождение ставок, расчётные периоды, читаемые пробелы, недопустимый график, назначенный ответственный и безопасный формат Decimal входов, включая экспоненциальную запись.
- Точная контрольная кривая и компоненты, неизменность snapshot, неизвестные ставки, нулевой горизонт; сохранённый и явно привязанный профиль; чужой доступ 404; чужой/общий профиль не используется; нет dispatch/мутаций.
- Frontend production build, ESLint и Ruff новых модулей/API кривой и их тестов проходят. Расширенная проверка старых `incidents.py`/`stroy_control.py` выявляет оставшийся lint-долг (импорты, длинные строки, аннотация `Any`); общая стилистическая переделка этих файлов не выполнялась.
- Две дополнительные независимые read-only критики GPT-6.1 Sol (low) нового UI и API/кривой не нашли подтверждённых actionable ошибок. Критики проверяли исходники; браузерные проверки выполнены интегратором.
- IAB: 112 000 ₽ при 8 ч; стрелка влево — 104 000 ₽ при 7,5 ч; ⓘ раскрывает фактические компоненты; Escape закрывает с возвратом фокуса; случай без входов показывает короткое сообщение. Проверена ширина окна на узком экране, исправлено обрезание.
- После правок IAB: явная сценарность и условие, переход к правильной карточке с фокусом, источник и ставки, повторный клик ⓘ, Escape сначала закрывает подсказку, затем окно; пустой случай показывает входы и владельца. Проверены узкая ширина и область ⓘ 44×44. API перезапущен с последним кодом.
