# Обновление фронтенда на сервере

Изменения интерфейса находятся в `src/`. `Dockerfile.frontend` копирует их в образ,
а `docker-compose.yml` также монтирует `./src` с хоста. Push обновляет Git-репозиторий;
запущенные на сервере контейнеры он сам по себе не обновляет.

Текущий контейнер запускает Vite на порту 5173. Это существующий режим демостенда,
а не отдельный production-образ со статической раздачей собранного `dist`.

## Адрес API

По умолчанию браузер обращается к `http://<hostname страницы>:8000`.
Для локального запуска это `http://127.0.0.1:8000`, для серверного — адрес сервера.

Если API доступен через другой адрес или HTTPS, задайте в корневом `.env`:

```dotenv
VITE_API_URL=https://api.example.ru
FRONTEND_HOST=stroy.example.ru
```

Укажите публичный адрес, доступный **браузеру пользователя**, без `/api/v1`
и завершающего слеша. Для HTTPS-страницы API также должен быть доступен по HTTPS.
`FRONTEND_HOST` — домен фронтенда без протокола и порта. Он добавляется в список
разрешённых хостов Vite; без него запросы по внешнему домену получают 403.
При доступе по IP эта настройка не требуется.
Если фронтенд и API обслуживает один reverse proxy, укажите его общий origin,
например `https://stroy.example.ru`; proxy должен направлять `/api/v1` и `/media` в API.

При разных origin добавьте реальный адрес страницы в `CORS_ORIGINS`
в серверном `backend/.env`, например:

```dotenv
CORS_ORIGINS=["https://stroy.example.ru","http://127.0.0.1:5173"]
```

Изменение настроек API требует пересоздания контейнера API.

## Обновление

После push, в рабочей копии проекта **на сервере**:

```bash
git pull --ff-only origin main
docker compose config --quiet
docker compose up -d --build --no-deps --force-recreate --renew-anon-volumes frontend
docker compose ps frontend
docker compose logs --tail=80 frontend
```

Команда предполагает уже работающий backend. `--renew-anon-volumes` обновляет
анонимный том зависимостей фронтенда `/app/node_modules` из нового образа.
Именованные тома базы и хранилища эта команда не затрагивает.

Для первого запуска всего стенда нужны серверный `backend/.env` и внешние файлы
модели, указанные в `backend/weights/README.md`. Выполните
`docker compose up --build -d`; API применяет миграции при старте.
Успешная проверка только фронтенда не подтверждает готовность базы, модели и камер.

## Проверка

Откройте адрес фронтенда, войдите и проверьте загрузку объектов.
В Network запросы `/api/v1` должны уходить на адрес API сервера.
После смены адреса API пересоздайте frontend и обновите страницу.

Автоматические проверки интерфейса с тестовыми ответами API:

```bash
npm run build
npm run lint
npm run test:ui
npm run test:browser
```

Браузерные проверки подтверждают поведение интерфейса; работу настоящего
backend на конкретном сервере проверяют отдельно.
