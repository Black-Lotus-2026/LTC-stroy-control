# Ракурс камеры: эталон, перенос и проверка

Подрядчику выгодно отвернуть камеру от нарушения. Поэтому система знает, как должна висеть каждая камера, и сообщает, если ракурс изменился без согласования.

## Кто что решает

| Кто | Что может |
| --- | --- |
| Система | Сравнивает каждый кадр с утверждённым ракурсом и создаёт событие. Сама новый ракурс не принимает |
| Ответственный за объект | Вернуть камеру и нажать «Камера возвращена — проверить». Предложить новый ракурс с причиной. Попросить перенос камеры до срока |
| Администратор | Утвердить ракурс, утвердить или отклонить предложенный, согласовать или отклонить перенос. Решение «Принять новый ракурс» закрывает событие как согласованное смещение |
| Наблюдатель | Только смотрит |

Своё же предложение ответственный не согласует. Утверждения, предложения и переносы хранятся у камеры на сервере, у каждого есть автор и время. Последние записи видны в «Истории ракурса» в настройках источника.

## Как сравнивается кадр

Одинаково в браузере (`src/sverka/lib/view.ts`) и на сервере (`backend/app/services/camera_view.py`):

1. Кадр уменьшается до 64×36, и строятся контуры: модуль градиента яркости. Контуры почти не меняются от света, туч и вечера.
2. Кадр делится на 4×3 клетки. В каждой считается корреляция контуров с эталоном, итог — медиана по клеткам. Часы камеры в углу или самосвал перед объективом занимают несколько клеток и оценку не решают.
3. «Совпадение» — медиана при сдвиге не больше точки (допуск на дрожание мачты). Поиск сдвига в пределах ±8 × ±5 точек показывает, куда повернули камеру: если кадр совпадает только со сдвигом, камеру повернули.
4. Только в браузере дополнительно проверяется:
   - тёмный однородный кадр — «объектив закрыт»;
   - резкость на 256×144, отнесённая к контрасту, — «изображение размыто». Сумерки снижают и резкость, и контраст, а размытый объектив — только резкость.

Пороги: от 0,6 совпадает, ниже 0,45 не совпадает, между ними состояние не меняется. «Ракурс изменён» ставится после 8 плохих кадров подряд (около 16 с), «совпадает» — после 3 хороших.

Проверено на кадрах из `docs/ui-concept/assets` (`backend/tests/test_camera_view.py` — на синтетических сценах):

| Изменение кадра | Совпадение |
| --- | --- |
| Тот же ракурс темнее в 2,5 раза | 1,00 |
| Самосвал закрывает треть кадра | 1,00 |
| Самосвал закрывает половину кадра | 0,83 |
| Сдвиг на 1 % (качается мачта) | 0,92 |
| Поворот на 3 % | 0,61 — ещё совпадает |
| Поворот на 6 % | 0,22 |
| Поворот на 20 % | 0,05 |
| Другая сцена | 0,06 |

Все кадры в таблице — с часами камеры в углу. Без медианы по клеткам поворот на 20 % давал 0,49, и смещение не находилось.

## Что происходит

- **Несогласованное смещение.**
  - Плашка на кадре становится красной, вердикт говорит «Ракурс камеры изменён».
  - Кадры этой камеры перестают учитываться в сверке техники.
  - На сервер уходит событие `VIEW_CHANGED`: снимок «сейчас», «до смещения» (последний совпавший кадр) и эталон, который сервер добавляет сам.
  - Ответственный получает задачу со сроком. Если камера к сроку не вернулась, событие уходит руководителю.
- **«Камера возвращена — проверить».** Сервер сразу берёт три свежих кадра камеры и сравнивает их с эталоном. Совпали — событие закрыто как «Камера возвращена». Не совпали — остаётся открытым. Beat и детектор для этого не нужны. Кадр HTTP-камеры читается без OpenCV, RTSP читается через OpenCV.
- **«Принять новый ракурс»** (администратор). Текущий кадр становится эталоном, открытые события о ракурсе камеры закрываются как «Смещение согласовано».
- **Согласованный перенос.**
  - Пока перенос действует, камера на паузе: событий о ракурсе нет, кадры в сверку не идут.
  - Утверждённый новый ракурс завершает перенос.
  - Если срок вышел, а нового ракурса нет, ответственному приходит событие `VIEW_MOVE_OVERDUE`. Проверяется раз в минуту через beat и при каждом открытии объекта.

## API

Все запросы требуют входа и прав на объект.

```
GET    /api/v1/projects/{project_id}/camera-views
PUT    /api/v1/projects/{project_id}/cameras/{camera_id}/view/reference           {snapshot_base64, note}
POST   /api/v1/projects/{project_id}/cameras/{camera_id}/view/reference/approve   (администратор)
POST   /api/v1/projects/{project_id}/cameras/{camera_id}/view/reference/reject    (администратор)
POST   /api/v1/projects/{project_id}/cameras/{camera_id}/view/move                {until, reason}
POST   /api/v1/projects/{project_id}/cameras/{camera_id}/view/move/approve        (администратор)
POST   /api/v1/projects/{project_id}/cameras/{camera_id}/view/move/reject         (администратор)
DELETE /api/v1/projects/{project_id}/cameras/{camera_id}/view/move
```

Снимок проверяется как изображение: base64, не больше 4 МБ, открывается Pillow. Он пересохраняется в JPEG до 1280 px, поэтому SVG или HTML под видом снимка сервер не примет. Миграция `20261018_1200`.

## Ограничения

- Сравнение идёт в открытой вкладке, как и всё распознавание. Сервер сравнивает сам только при проверке «Камера возвращена».
- События о ракурсе пишутся только в смену. Ночью тёмный кадр иначе выглядел бы закрытой камерой.
- Поворот больше чем на ~13 % распознаётся как «другая сцена», без направления.
- Камере без утверждённого ракурса сравнивать не с чем. Ракурс утверждают при подключении камеры.

## Показ

1. Администратор: Настройки → Источники → «Утвердить ракурс по текущему кадру».
2. Повернуть камеру (на телефоне с IP Webcam — просто повернуть телефон). Через 16 с плашка станет красной, в очереди появится «Ракурс камеры изменён».
3. Включить «Эталон» под кадром: утверждённый кадр ляжет поверх живого.
4. Вернуть камеру, открыть разбор, нажать «Камера возвращена — проверить». Сервер сверит кадры и закроет событие.
5. Ответственный просит перенос, администратор его согласует. Камеру можно двигать: событий нет, вердикт говорит «Камера переносится».
