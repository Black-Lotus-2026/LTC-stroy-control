# Live-камеры MyVMS в демо

В общем демонстрационном объекте выберите **Live-камеры MyVMS**.
Доступны переключение Camera 2 / Camera 3, непрерывное MP4-видео,
кадр с рамками YOLO, пауза анализа и сводка наблюдений за сеанс.
Первый анализ начинается при открытии экрана. Запросы идут последовательно:
следующий кадр запрашивается через две секунды после ответа предыдущего.
При уходе с экрана запросы и видеосоединение закрываются.

Рамки относятся к тому JPEG-кадру, который показан во вкладке детекции.
В непрерывном видео рамки не накладываются: у него другое время воспроизведения.
Модель, нормализация классов и пороги совпадают с основным YOLO-пайплайном.
Внешние VLM не вызываются. Если модель недоступна, кадр остаётся доступным,
а ошибка выводится явно. Свежесть кадра ограничена 15 секундами.

Статистика — максимум объектов каждого класса на одном кадре за текущий сеанс
выбранной камеры, а не число уникальных машин. Неуспешный анализ не считается
пустым наблюдением. Данные не записываются в БД, не создают нарушения и не
сравниваются с историческим графиком демо-объекта. После закрытия экрана сеанс
сбрасывается. Это интерактивный demo live-анализ, не фоновый сбор 24/7.

## Локальный QA

Создайте закрытый файл `backend/var/myvms-demo.env` (каталог игнорируется Git):

```dotenv
MYVMS_DEMO_ENABLED=true
MYVMS_BASE_URL=http://your-vms-host:9786
MYVMS_USERNAME=your-login
MYVMS_PASSWORD=your-password
MYVMS_DEMO_CHANNELS=[1,2]
```

```bash
backend/.venv/bin/python tools/customer_control_demo.py --port 8991 --myvms-demo
VITE_API_URL=http://127.0.0.1:8991 npm run dev -- --host 127.0.0.1 --port 5193 --strictPort
```

Для прежней QA-базы добавьте `--resume-root /private/tmp/ltc-customer-qa.<suffix>`.
Без `--myvms-demo` launcher не читает файл live-камер; рабочий `.env` он также
не читает. Флаг загружает только пять перечисленных MYVMS-переменных.

## Сервер / Docker

Укажите эти же пять переменных в `backend/.env` и перезапустите API.
Compose уже передаёт этот файл в контейнер API. Нужны исходящий доступ
к HTTP-порту MyVMS (здесь 9786) и установленные веса YOLO. Порт клиента 9780
для этой интеграции не используется. По умолчанию live-демо выключено.
Для private VMS-сетей действует существующая `CAMERA_ALLOWED_NETWORKS`.
Локальные служебные адреса и перенаправления запрещены адаптером.

## Границы доступа

Все маршруты `/api/v1/live-demo` проверяют действующего пользователя и
явный `shared_demo` объект. Ни гостевой доступ, ни публикация live-камер
в частных объектах не предусмотрены. Каналы задаёт оператор сервера,
параметр произвольного адреса отсутствует. Предоставленные владельцем камер
учётные данные используются только сервером, отдельно от URL.

Для HTML video API выдаёт cookie HttpOnly на пять минут с отдельным purpose,
привязкой к пользователю, проекту, каналу и media path. Это не access token.
Видео обновляет соединение каждые четыре минуты; выключение пользователя
или публикации проверяется и на открытом соединении. Кадры, видео и анализ
отдаются с `private, no-store`. Серверное приложение должно работать через
HTTPS; если сам VMS поддерживает HTTPS, используйте его в `MYVMS_BASE_URL`.

Обработка ограничена двумя одновременными запросами YOLO на процесс,
восьмью секундами получения JPEG и восемью мегабайтами на кадр.
