# Ветка feature/ui-sverka: новый интерфейс в приложении

Концепция и прототип: [CONCEPT.md](CONCEPT.md), [prototype.html](prototype.html). Здесь — что из этого перенесено в настоящее приложение и как его сравнить со старым.

## Как сравнить

```bash
npm install
npm run dev
```

- Новый интерфейс: `http://localhost:5173/`
- Старый интерфейс: `http://localhost:5173/#legacy` (в меню пользователя пункт «Старый интерфейс»; в старом — кнопка «Новый интерфейс →» внизу справа)

Оба работают с одним API и одной базой. Переключение перезагружает страницу: у каждого интерфейса свои глобальные стили, они не подключаются одновременно.

## Что есть в новом интерфейсе

| Часть | Файл | Что делает |
| --- | --- | --- |
| Вердикт | `src/sverka/parts/Verdict.tsx` | Одна фраза о состоянии и одно действие. Смена состояния: старая фраза уходит вверх, новая приходит снизу. |
| Кадр и источники | `parts/Stage.tsx` | Кадр выбранного источника, рамки детекций, честные состояния: нет сигнала, кадр застыл, RTSP не поддерживается. Устаревший кадр выцветает. |
| Сверка этапа | `parts/Recon.tsx` | Этап по дате наблюдения, ожидаемая техника и факт, кольцо до порога, «не по этапу», «не учитываются», подсказка о похожем этапе. Силуэт перелетает с рамки на кадре в слот. |
| Очередь решений | `parts/Queue.tsx` | Свайп вправо — подтвердить, влево — ложное, с отменой. Новая карточка вылетает из слота техники. |
| План | `parts/Dock.tsx` | Свёрнутая лента этапов и шкала дня; вытягивается вверх в график, профиль этапа и матрицу «какая техника нужна по плану». В режиме записи по шкале можно перематывать. |
| Разбор события | `parts/CaseFile.tsx` | Снимки со всех источников, цепочка «План → Правило → Наблюдение → Качество данных → Вывод», решение с комментарием сохраняется на сервере. |
| Правило техники | `parts/RuleEditor.tsx` | Пять уровней, пороги времени, влияние на события сеанса, сброс к справочнику. Сохраняется на сервере. |
| Настройки | `parts/Settings.tsx` | Контроль, источники с проверкой связи, смена и объект. |
| Первый запуск | `parts/Setup.tsx` | Объект → план (файл или пример) → камера или запись → проверка готовности. |
| Движок наблюдения | `src/sverka/engine.ts` | Берёт кадры у камер и записей, отправляет на распознавание, ведёт учёт: что и когда замечено, когда анализ действительно шёл. |
| Модель | `src/sverka/model.ts` | Этап по дате, правила, оценка сверки, вердикт. |

## Правила честности, заложенные в код

- Нет распознавания — нет выводов. Ответ `model_ready=false` или недоступный сервис переводит технику в «нет данных», события не создаются.
- Отсутствие техники считается только за время, когда анализ действительно шёл. После перерыва счётчик начинается заново.
- Камера без сигнала или с застывшим кадром исключается из выводов, вывод помечается как ограниченный.
- RTSP показывается как «не поддерживается браузером» вместо подставной картинки.
- Вне смены и в первые 30 минут смены отсутствие техники не считается отклонением.
- Одно открытое событие на технику и этап: после перезагрузки страницы система подхватывает открытое событие из журнала, а не создаёт дубль.
- Подтверждение не равно устранению: вердикт остаётся, пока техника не вернётся.
- Новый API-клиент `src/sverka/api.ts` не подставляет демо-данные: ошибка видна на экране.

## Ограничения, которые интерфейс не скрывает

- **Анализ идёт в открытой вкладке.** Если вкладку закрыть, наблюдение останавливается. Постоянный сбор кадров на сервере (Celery-воркер) — отдельная задача.
- **Архива кадров нет.** В режиме «Сейчас» шкала дня показывает только текущий сеанс, перемотки нет. Перемотка работает в режиме записи.
- **RTSP** в браузере не воспроизводится. Нужен шлюз в MJPEG/HLS или серверный захват кадров; эндпоинт `/videos/frame` для этого готов принять RTSP-ветку.
- **Окно сверки** сохраняется на сервере; остальные параметры контроля пока хранятся в браузере, это подписано в настройках.
- **Журнал с выгрузкой акта** ещё не перенесён; пока он доступен в старом интерфейсе.
- **Профиль техники с сервера** для «Выемки грунта котлована» помечает бетононасос и автобетоносмеситель обязательными (94%), хотя справочник `final_pars.csv` для этого этапа даёт экскаватор, самосвал и бульдозер. Это вопрос к сопоставителю этапов, интерфейс показывает то, что считает сервер.

## Как проверялось

- `npx tsc --noEmit`, `npx eslint src/sverka src/main.tsx` — без ошибок.
- Бэкенд: 47 тестов.
- В браузере на локальном стенде: вход, первый запуск, загрузка примера плана, запись с датой начала 5 мая (этап «Выемка грунта», день 4 из 21), три MJPEG-камеры через сервер, отключение камеры, застывший кадр, событие «самосвал не замечен», событие «экскаватор не по этапу», разбор события, решение с комментарием на сервере, свайп и отмена, изменение правила техники, настройки смены.
- Обученных весов на стенде нет, поэтому ответ распознавания в браузерном тесте подменялся тестовым скриптом. В коде приложения подмены нет.
