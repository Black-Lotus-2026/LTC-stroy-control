# Что нужно от бэкенда: найдено при переносе нового интерфейса

16 октября 2026, дополнено 18 октября после слияния с `main`. Ветка `feature/ui-sverka` бэкенд не меняет: интерфейс работает с сервером из `main` и обходит проблемы на своей стороне. Ниже то, что стоит исправить на сервере, по убыванию критичности. Для части пунктов уже есть готовая реализация: она была в коммите `7d35728` этой ветки и откатана в `3f5c8a0`. Посмотреть: `git show 7d35728 -- backend/`.

Темы демо-данных и подстановок здесь нет специально: для защиты оставляем подмены, интерфейс их помечает.

## Что уже закрыл `main` (18 октября)

- Пункт 2 в части событий и плана: `GET /incidents`, `POST /incidents` и запросы плана требуют объект и проверяют владельца; неизвестный этап — 404, а не первый попавшийся. Список объектов по-прежнему отдаёт не-администратору объекты без владельца, хотя дальше они ему недоступны (пункт 21).
- Пункт 13: очистка плана без `project_id` запрещена, этап ищется только по UUID.
- Пункт 9: у события есть `captured_at` при создании и `first_seen_at` в ответе; время снимков берётся из него. Интерфейс перестал писать время в описание.
- Пункт 10 наполовину: история события `GET /incidents/{id}/events` с автором и временем. Комментария к решению по-прежнему нет.
- Пункт 17 наполовину: `stage_probability` больше не подставляется, а `machinery_type` по-прежнему «Экскаватор».
- Примеры INC-042/043 для пустого журнала убраны.
- Пункт 4 в малом: повторную проверку исправления сервер делает сам (`alert_service.verify_incident` берёт кадр камеры и распознаёт), раз в минуту через Celery beat. Постоянного наблюдения без вкладки по-прежнему нет.

## Порядок, если делать по одному

1. Пункт 1: без него демонстрация на котловане выглядит ошибочной.
2. Пункты 2, 13 и 3: небольшие правки, убирают смешивание и потерю данных и зависание.
3. Пункт 14: профиль этапа из базы вместо расчёта на каждый запрос — сервер перестанет тормозить при открытии плана.
4. Пункт 5 через готовый `/videos/frame`, затем 8 на его основе.
5. Пункты 6, 7, 9: интерфейс сразу перейдёт с браузерных пометок на серверные.
6. Пункт 4: самая большая задача, превращает прототип в постоянный контроль.
7. Пункты 18, 21 и 23: небольшие и мешают показать задачи на стенде; 19 и 22 — перед тем как показывать журнал и сводку руководителю.
