# 0003. Синхронный SQLAlchemy

**Решение.** Работаем с базой синхронно, без `asyncio`-драйвера.

**Почему.** Celery-воркер синхронен по своей природе. При асинхронном
SQLAlchemy пришлось бы либо держать два слоя доступа к данным (один для
API, другой для задач), либо оборачивать вызовы в event loop внутри
воркера. Синхронный вариант даёт один слой на всё приложение.

Потери производительности в нашем масштабе нет: FastAPI выполняет
обработчики, объявленные обычным `def`, в пуле потоков, и на нагрузке
прототипа узкое место — детекция, а не база.

**Граница применимости.** При росте числа одновременных подключений
(например, живая трансляция событий через WebSocket на десятки клиентов)
решение стоит пересмотреть — но переписывать придётся только слой доступа
к данным, а не логику.
