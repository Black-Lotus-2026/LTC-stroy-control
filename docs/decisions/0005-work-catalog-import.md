# 0005. Импорт справочника видов работ

**Что это за файл.** «Сводный перечень строительных работ_ЛТЦ.xlsx» от
организаторов — иерархический справочник на 377 наименований: два корневых
раздела («Подготовка территории», «Выполнение строительно-монтажных работ»),
21 подраздел, дальше до пятого уровня вложенности. Колонки размечают
применимость работы к типу объекта: жильё, образование, здравоохранение,
спорт, культура, административные здания, ДОУ, офисно-деловой центр, дороги.

**Чего в файле нет: сроков и зон.** Это справочник «какие работы бывают», а
не календарный план. Поэтому импорт создаёт только виды работ (`work_types`).
Задачи календарного плана (`schedule_tasks`) — с зоной и датами — приходят из
отдельного источника.

## Две особенности файла, которые пришлось учесть

**Коды, съеденные Excel.** 19 кодов второго уровня хранятся в файле как даты:
вместо «10.1.» лежит число 45667, то есть 10 января 2025 года. Excel так
поступает с текстом вида «10.1» при открытии. Восстановление обратное:
`день.месяц` → код. Проверено на всех 19 строках, включая переход между
разделами («12.1.» = 12 января).

Без этого шага 19 подразделов остались бы без номеров, а вместе с ними
потеряли бы место в дереве все их потомки.

**Строки без номера.** Код заполнен только у 127 строк из 377. Стандартной
группировки строк (outline level) в файле нет, отступов в стилях — тоже.
Строка без номера — это подпункт последней пронумерованной строки: так они
и восстанавливаются. Проверяется тестом на реальном файле: после разбора ни
одна запись, кроме двух корневых, не остаётся без родителя.

## Решения по реализации

**Разбор отделён от записи в базу.** `parse_work_catalog()` возвращает
плоский список с восстановленной иерархией и не знает про SQLAlchemy. Файл
можно проверить командой `--dry-run`, не трогая базу, и протестировать без
поднятой базы.

**Повторный импорт не создаёт дублей.** Строки сопоставляются по номеру
строки исходного файла (`source_row`), он же хранится в записи. Второй запуск
той же команды обновляет 377 записей и не создаёт ни одной. Номер строки,
кроме того, позволяет объяснить происхождение любой записи, не открывая xlsx.

**Удаление отсутствующих — только по явному флагу.** `--replace` каскадно
удалит правила, ссылающиеся на исчезнувшие виды работ, поэтому по умолчанию
выключен.

**Файл справочника лежит в репозитории** (`data/work_catalog.xlsx`, 35 КБ).
Импорт должен воспроизводиться на чистой машине одной командой, а не зависеть
от того, что у кого-то осталось в загрузках.

## Тесты идут по настоящему файлу

Синтетический пример не воспроизвёл бы ни дат вместо кодов, ни строк без
номеров — то есть проверял бы ровно то, что заведомо работает. Тесты
пропускаются, если файла нет в окружении.
